# SME 迭代计划：对标第一梯队

> 目标：把 SME 从"能力集达标"推进到**第一梯队**（Mem0 / Zep / Graphiti / Letta /
> ChatGPT 记忆的能力 + 工程成熟度 + 可背书）
> 铁律：**全部迭代为增量式**——独立模块/独立开关/默认行为不变/快照兼容；
> 每项合入前跑"全关回归"（v1 行为零漂移）
> 依据：本次实测（精准度/消融/性能）+ 全量代码审查结论

### 1.2 关键结论（本次实验 + 审查）

1. **检索主体达标**：v1 全关 91-93%，与历史基线一致（重构零回归）；05/02/04/03
   为无损增强（92%）
2. **全开/知识库模式弱的主因（英语流）**：qapair 回放污染（闲聊问题以 0.99 分
   置顶）+ extraction 过滤（记忆 684→332）+ noise 英语误伤；**中文对话场景未验证**
3. **qapair 查询性能缺陷**：每查询对全部问答对逐条 embedding（187 对 → 1.1s）
4. **关键词通道不可缺**：keyword_weight=0 时命中率 91%→19%（hashing 流）
5. **衰减/演化开关对命中率无影响**（消融 4 组 56-57 分）——已排除为干扰因素
6. **代码审查遗留**：BM25 中文单字切分、无文档切片导入、无 rerank、
   consolidation/graph O(n²)、10 万条加载 47s、噪音误伤 ~20% 真实记忆

## 二、迭代清单（按优先级）

### P0 · 性能与可用性（第 1-2 周）

#### 迭代 1.1 QAPair 问题向量缓存（全开/知识库检索 1.1s → ≤50ms）

- **根因**：`QAPairStore.lookup()` 对每个问答对逐条 `embed_one`（187 对 × BGE ≈ 1.1s）
- **方案**（模块内部，不动引擎）：
  1. 写入问答对时缓存问题向量（QAPair 旁车/内存字典，快照兼容：可选键）
  2. lookup 改为缓存向量矩阵一次 matmul（187 对 → ~5ms）
- **验收**：全开配置检索 ≤50ms；15 项回归（重建测试资产后）全绿；关闭模块零变化

#### 迭代 1.2 BM25 中文升级（CJK bigram）

- **现状**：`utils.tokenize` 对 CJK 按单字切分，"违约金"→"违/约/金"，倒排匹配噪声大
- **方案**：CJK 段生成 1-2 gram（"违约金"+"违约"+"约金"），保留拉丁原逻辑
- **验收**：中文法律/医疗术语检索命中率提升（中文测评集）；英文行为不变

#### 迭代 1.3 文档导入工具（知识库场景关键）

- **定位**：把 SME 从"记忆引擎"补成"记忆+知识库引擎"（法律/医疗资料场景）
- **方案**：
  1. `engine.import_documents()` 或独立 CLI：按中文条款/段落正则切分（`第X条`、句号），逐条入库
  2. 自动 metadata：`来源` / `条款号` / `文档名`（检索可 `metadata_filters` 圈定）
  3. 摘要-原文两级结构：复用 parent/children + summary 边——检索用摘要/标题记忆（短向量精度高），命中沿边取原文（RAG chunk→原文映射的 SME 版）
- **验收**：导入一部法律/一批资料后，"违约金怎么约定"类中文提问命中对应条款

### P1 · 准确性与工程质量（第 3-4 周）

#### 迭代 2.1 噪音抑制误伤修复（~20% → <5%）

- **方案**（参数/白名单，不动模块逻辑）：
  1. `min_density` 0.05 → 0.10；`template_penalty` 0.4 → 0.3（可配置）
  2. 短句白名单：`fact_kind="fact"` 或提取事实跳过模板度惩罚
- **验收**：消融"单开 06" hit@1 ≥ 160；模板霸榜压制能力不回退

#### 迭代 2.2 噪音重排候选窗口

- **现象**：模板句占满 top5 时真实记忆（第 6 名）被提前截断救不回
- **方案**：检索候选窗口扩大（取 max(top_k, 20) 再截断，参数可配，默认行为不变）
- **验收**：模板霸榜场景真实记忆稳定进入 top5

#### 迭代 2.3 Rerank 接入（可选精排）

- **方案**：`ranking.register_scorer` 扩展点已就绪——提供 bge-reranker 适配示例（检索后精排）；做成可选模块开关
- **验收**：中文知识库场景 top5 精准度提升；默认关闭零影响

#### 迭代 2.4 知识库预设排序调优

- **现状**：静态知识场景下 freshness/recency 权重（合计 0.16）无意义
- **方案**：知识库预设内 `ranking.freshness/recency` 调低、`semantic` 调高（预设级参数，不碰默认）
- **验收**：知识库预设命中率提升，聊天预设不变

#### 迭代 2.5 rules 提取鲁棒性

- **现象**："用户不喜欢喝咖啡了" 与 "用户喜欢喝咖啡" 因"了"字实体分裂
- **方案**：rules 提取去尾语气词（了/吗/呢/吧）归一化
- **验收**：时序覆盖用例在含语气词句子上通过

#### 迭代 2.6 10 万条加载提速（47s → ≤30s）

- **方案**：Region 几何重建与 BM25 重建并行化（thread pool）；向量归一化跳过重复计算
- **验收**：10 万条加载 ≤30s；规模压测通过

### P2 · 产品化与可背书（第 5-6 周）

#### 迭代 3.1 标准评测资产（benchmarks/）

- **现状**：实验工程已删，无自动化测试与评测资产（**重建**）
- **方案**：
  1. 重建 `benchmarks/` 标准目录：183 题考问 + 30 题跨措辞 + **新增中文知识库题集**
     （法律/医疗分条导入考问）+ 指标统一（命中率/语义命中/延迟/成本）
  2. `python -m sme.benchmark` 一键评测入口（保留现有压测）
  3. 回归测试重建：全关回归（v1 行为零漂移断言）+ 12 模块专项 + 全开压测
- **验收**：一条命令复现全部数据；每次迭代合入前全关回归零漂移

#### 迭代 3.2 可观测性面板

- **方案**：`/metrics` 端点扩展（命中率/延迟分位/token 成本/记忆分布）+ 导出报告
- **验收**：20 轮对话自动生成报告

#### 迭代 3.3 存储后端完善

## 五、验收总门（全部完成后判定"进第一梯队"）

1. 全开模式检索延迟 ≤50ms（性能达标）
2. 噪音误伤 <5%（准确率达标）
3. v1 全关命中率保持 ≥90%（无回归）
4. 中文知识库场景（法律/医疗分条导入）命中率与 RAG 中配持平或更优
5. 一键命令复现全部评测数据（可背书）
6. `pip install sme` 全新环境可用（产品化）
7. 全关回归零漂移（快照/行为等价）
